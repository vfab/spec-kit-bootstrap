# Agentic Spec-Driven Development System

This project uses **spec-kit** to define *what* to build and a **multi-agent system** to define *how* to build it correctly.

## Bootstrap

Two bootstrap scripts are provided depending on how much scaffolding you need:

Both scripts are safe to run on existing projects — they skip files that already exist.

```bash
# Minimal setup (README, process, constitution, basic agents)
bash bootstrap-basic.sh

# Full setup (all of the above + architecture, ADR template, how-to guides, all agents)
# Also upgrades existing files with a .bak backup
bash bootstrap-full.sh
```

## Setup

Install spec-kit if it isn't already available:

```bash
command -v specify &>/dev/null || uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
```

> **Note:** Both scripts check for spec-kit on startup and install or upgrade it automatically via `uv`. `specs/` is created by spec-kit itself on first `specify create` and is not pre-created by the bootstrap scripts.

## Start

```bash
specify create
```

Then prompt the agent:
> "Use the bootstrap protocol and begin discovery"

## Development Process

1. `specify create` — define the spec
2. Agent discovery (Q&A)
3. `specify refine` — iterate on the spec
4. Architect validation
5. `specify tasks` — break work into tasks
6. TDD execution (write tests first, then implement)
7. Review
8. Deploy
9. ADR tracking for key decisions

See [docs/process.md](docs/process.md) for details.

## Agent System

Agents are defined in the [`agents/`](agents/) directory:

| Agent | Responsibility |
|-------|---------------|
| [Architect](agents/architect.md) | Own architecture, validate specs, create ADRs |
| [Implementation](agents/implementation.md) | Write production code |
| [Test](agents/test.md) | Write and run tests |
| [Reviewer](agents/reviewer.md) | Code review and quality gates |
| [DevOps](agents/devops.md) | CI/CD and deployment |
| [Product](agents/product.md) | Requirements and prioritization |

## Engineering Principles

See [docs/constitution.md](docs/constitution.md):

- Simplicity, Maintainability, Security first
- All work originates from a spec
- Tests before code (TDD)
- Layered architecture: API → Service → Domain → Data
- Propose improvements; do not auto-apply major changes
